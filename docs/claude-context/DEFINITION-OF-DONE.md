# DEFINITION OF DONE — a deliverable is not finished until its list is complete

Check the matching list before calling anything done. Prevents orphaned, half-shipped work.

## Any deliverable (baseline)
- Ran the output pipeline: voice-scrub, named-entity-check (holds), verify-work.
- Saved to a tracked hub path; reference records mirrored to Notion.
- Manifest line logged; any follow-up captured as a Task.
- Addie approved anything that goes public.

## Field note (website article)
Not done until all 5 publish points are hit, or it is orphaned:
1. The article file itself in deploy-live.
2. Added to field-notes.html hub.
3. Added to sitemap.xml with today's lastmod.
4. Added to llms.txt list.
5. Cross-linked from 2-3 older articles (every article has >=3 inbound internal links).
Plus: title <60 chars; meta <155; canonical/OG/Twitter tags; BlogPosting/Article JSON-LD incl. image;
nav "Field notes" active; cta-band with the Fit Call button; FAQ (2+) with FAQPage schema; footer email
signup. Then follow WEBSITE-EDIT-PROTOCOL.md to deploy.

## Website change (non-article)
- Followed WEBSITE-EDIT-PROTOCOL.md (pull-rebase, register row, no force-push).
- Mockup shown (mobile + web) and approved.
- Cache stamp bumped if a shared asset changed.
- Deployed via publish.sh; live page verified; register row closed.

## Proposal / SOW
- Scope-based, deliverables not hours; pricing tier reasoning shown.
- Voice + holds clean; no confidential metrics.
- Saved to client folder; logged as a Task with the next follow-up + date.
